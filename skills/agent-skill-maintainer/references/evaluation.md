# Evaluation

Establish a no-skill baseline before evaluating the candidate. Compare the same model, prompt, artifacts, and tools without revealing expected findings.

Formal platform evidence uses platform-specific profiles: Codex remains default-only, while Claude Code may use the explicitly labeled `current-environment-bound` profile with model `k3`. The controller commits that profile's endpoint, model selectors, and salted credential identity before execution, and the native transcript must report only canonical model `k3`. The result proves only the bound working environment and must not be generalized to default-route portability. A separate default-only Claude portability probe is nonblocking when credentials are unavailable; it is limited to one structured reason-code disclosure and cannot count as a passed platform case.

A publishable same-model blinded A/B must use a fixture held out from optimization iteration. Before either output exists, lock the entire fixture and put its canonical SHA-256 commitment into the randomized assignment. That commitment covers the prompt, target hashes, complete runtime bundles, candidate identity, rubric, thresholds, platform requirements／limits, and tool profile. Do not send that identity-bearing fixture directly to a generator or Judge. Derive one label-specific generator view containing the shared specification plus only that opaque label's target hashes and observed runtime identity, including the harness-derived CLI-smoke commitment; it must omit baseline/candidate field names and the assignment map. Derive the Judge view from the shared specification and opaque labels, where each label carries its generator-view commitment, raw-output hash, and opaque runtime-bundle commitment; it must not expose either tree fingerprint or candidate identity. This prevents the Judge from comparing a generator output's view hash to the different Judge-view hash. Require both raw generator outputs, both generator-session records, the raw Judge output, and the Judge-session record to carry the locked-input commitment plus the SHA-256 of the exact role-specific input view. Each private session also carries the SHA-256 identity of the raw output that already existed when the session record was captured. Run baseline and candidate in distinct sessions with the same model and tools. Give every behavior stable pass-clause IDs in the locked fixture. Each generator records non-empty evidence for every clause under that same behavior, whether the overall verdict is pass, fail, or insufficient; the Judge adjudicates the same complete clause map for both labels. This prevents evidence for a required boundary from being omitted, or left under an adjacent behavior and then lost through item-local review. A third session owns adjudication, sees only labels A and B, records one `pass`, `fail`, or `insufficient_evidence` verdict plus a redacted rationale and private evidence summary for every locked behavior, and completes before unblinding.

Measure discovery, false positives, ownership, closure, actionability, correction count, elapsed reference time, tool calls, artifact bytes, and any fixture-specific structural limit. Lock quality and cost thresholds before viewing candidate results. The local measurement builder reads the unpublished outputs and event records, computes UTF-8 bytes, tool-call counts, heading counts, and source hashes, and verifies the resulting measurement before raw sources are removed. Its `measured_at` must be at or after both generator completions and at or before Judge start; a pre-completion or post-Judge measurement is invalid. Deterministic code validates identities, time ordering, hashes, and derivation; it never assigns semantic verdicts.

After unblinding and before any supported-platform case starts, have the locked neutral controller sign a short-lived challenge containing the exact evaluation and candidate identities, issue/expiry times, one unique nonce for every platform positive／negative case, and the observed platform version, executable hash, and fixed execution-profile hash. The same controller—not the harness caller—then starts each provider with fixed argv: Codex uses an ephemeral read-only sandbox without user config or project rules, while Claude Code uses `dontAsk`, project/local settings, an empty strict MCP configuration, and only `Glob`, `Grep`, and `Read`. The controller records start/completion time itself, rejects completion after challenge expiry, validates the response and native transcript, and signs a per-session receipt. The platform's final response echoes only its fixed challenge identity, installed-copy identity, controller-supplied start time, objective booleans, and non-empty evidence; it never supplies completion time. Retain complete Codex JSONL and complete Claude Code `stream-json`, including Claude init, paired tool-use/tool-result events, and final structured result. Positive cases must demonstrate a confined read; negative cases must not read the target. After four controller-signed receipts exist, the controller signs a completion attestation at its own `attested_at`; caller-authored session records are not accepted. Every session binds its workspace, output/transcript hashes, provider nonce, tool count, and tool-sequence hash. Challenge and provider nonces use disjoint namespaces. The private key must be an absolute, owner-only regular file, not a symlink, and its real path must remain outside both candidate and current run trees. `eval-bind` verifies every signature, lifetime, runtime/profile commitment, transcript policy, live installed tree, workspace binding, response hash, nonce, tool sequence, and post-unblind time before deriving flags and `validated_at` from signed `attested_at`. Later validation reparses embedded transcripts and signed evidence instead of trusting copied summaries.

The publishable aggregate is schema v5 and must be rebuilt by `eval-bind` from the locked fixture, assignment, exact input-view identities, private sessions, raw outputs, complete Codex JSONL transcripts, timestamps, and post-unblind platform source. A generator transcript is valid only when it has one provider thread, one complete turn, paired tool starts/completions, no error event, a final agent message byte-identical to the raw output, exactly one eval-bind smoke, and exactly one combined runtime observation. A provider may add one quoted `/bin/zsh -c` or `/bin/zsh -lc` execution wrapper around an exact `/bin/zsh -lc` command; the verifier removes only that one syntactic layer without executing it, then applies the full policy to the inner command. Multiple wrappers, suffixes, or injected commands remain invalid. All remaining tools are limited to the fixture's read-only todo/read allowlist inside the supplied workspace; network tools, writes, private/global/candidate paths, and duplicated required commands fail closed. Measurement uses that paired sequence as the authoritative tool count; dropping or replacing events changes the session commitment and fails. The Judge receives one exact identity-neutral bundle containing the Judge contract plus opaque A/B outputs; it runs with zero tools, so neither a candidate fingerprint in the original generator response nor a private mapping file can become Judge evidence. The fixture also locks an independent controller version, live source SHA-256, and public key. For every platform case, the neutral controller owns the prompt, platform-specific minimal environment, provider argv, project root, and canonical project installation. Its short-lived challenge commits the executable/profile, salted environment identity, prompt-template identity, and installation path before execution. Caller prompt text is always rejected. Codex rejects provider route, model, and proxy overrides. Claude Code requires the committed endpoint, canonical `k3` selector, and salted credential identity while rejecting proxies, alternate-cloud routing, undeclared selectors, and profile substitution. A default-route profile must use a provider-native model name or built-in alias rather than a user-specific custom-provider alias. The controller copies only regular files without following links, requires the source and installed tree to match the candidate before execution, and rechecks both complete trees afterward. A positive transcript must prove successful byte-exact reads of the installed `SKILL.md` plus the evaluation and security references; a negative transcript must prove no read. The signed completion stores prompt/environment/template/install commitments, before/after tree identities, and the three required-read content hashes, so later evidence replay verifies transcript bytes without reopening the temporary platform project. The neutral controller also separately parses the raw benchmark transcripts and platform responses, enforces the same tool profile without importing the candidate scorer, derives the A/B headline counts, regressions, costs, and platform pass, then signs the exact source/result payload. Candidate code verifies that attestation but cannot replace it with its own scorer. The local-only binding records every source and attestation identity; later validation rebuilds and canonical-compares the manifest, adjudication, measurement, platform summary, and aggregate. The isolated A/B runtime workspaces are deliberately not copied into the binding: their session paths remain readable until the publication gate closes because every validation reruns the exact smoke and tree identity. A public-only, hand-authored, unsigned, or candidate-only binding is not a gate input. `evaluated_at` comes from the latest signed platform completion; all other fields are re-derived. Judge rationale intended for public evidence must already be redacted. Build the final candidate snapshot with the confirmed Skill path, matching frontmatter name, mode/path/blob tree fingerprint, and locked fixture path/raw SHA-256. Tree identity includes the complete relative path, regular-file mode, and blob bytes. `eval-bind --candidate <candidate-root>` re-reads the exact fixture and live neutral-controller source, rejects links and special files, compares their commitments, recomputes the live tree before and after every target hash, executes the exact read-only CLI smoke in each runtime, and derives the binding. Branch transition, apply, and publication validation repeat the controller, fixture, candidate, and exact-HEAD checks. Any missing transcript, attestation, source, workspace, commitment, gate, or HEAD-tree match blocks publication. Schema v2, v3, and v4 summaries remain historical only.

The held-out A／B workspaces must each contain the complete Skill tree, including every runtime library and schema loaded by the CLI. A target-file subset may focus review evidence, but it is not a runtime bundle. Each private generator session names the exact observed workspace and expected smoke record. The builder independently executes `node scripts/maintainer.mjs eval-bind` in that workspace, compares the captured exit/stdout/stderr and before／after tree identity with the session record, and rejects any write. The candidate must reach the evaluated command's deliberately omitted-argument boundary; the baseline may instead report that the new command is unknown, because absence of that behavior is part of the comparison. Module, schema-load, or syntax failures are not acceptable for either side. The builder also recomputes the workspace's full tree fingerprint and file count and requires the raw generator output to carry their identities. Only the redacted runtime-bundle identity enters public session evidence.

A Preview or stable release requires:

- 100% safety gate;
- exactly one passed documentation-impact check recording `updated`, `not-required`, or an explicitly permitted `upstream-follow-up`;
- at least one core quality metric better than baseline;
- no core quality regression;
- false-positive and cost values within locked limits;
- all platforms claimed as supported passing installation, positive and negative triggering, and local analysis.

Equal or worse results are not evidence of benefit and block publication. Public evidence may contain only synthetic, non-attributable adjudication summaries, measurements, and derived aggregates. Raw outputs, private evidence locators, conversations, and private code remain local.

## Stable Provider gate

A stable candidate additionally requires exactly one isolated, `controlled-redacted-real-usage` case for each formal Provider: Superpowers, Spec Kit, OpenSpec, BMAD Method, and Matt Pocock Skills. Every case must match the Profile version and immutable Release commit, use only allowlisted command identifiers, retain a unique artifact owner, prove fallback and safety, and record a criteria-based baseline/candidate quality comparison with at least one improvement and no regression. It also records elapsed seconds, tool calls, and artifact bytes for cost visibility without collecting or estimating Token usage. The primary Provider installation and configuration directories must remain unchanged and no remote write may occur. Host-agent runtime caches, logs, and application state are outside this Provider-installation assertion and must not be presented as Provider writes. GSD is legacy and is excluded from this count.

Codex and Claude Code must each pass installation, positive trigger, negative non-trigger, Provider selection, artifact bridge, fallback, and local-only analysis checks on the same candidate.

The aggregate is bound to the candidate Skill fingerprint. Missing, duplicated, synthetic, drifted, unsafe, or worse cases block `stable_candidate_ready`. That pre-release state allows only a Release preview; `publication_verified` remains false until the exact official tag and Release are read back after a separately confirmed publication.
